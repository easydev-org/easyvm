# v0.0.2 — the vocabulary, simplified

`v0.0.1` is the baseline: 147 declared keys (81 step keys, 66 subkeys, 42 retired). Everything
below is a proposal, with the reason it is a proposal rather than an opinion.

**The rule this pass is held to is the one already in `PRIMITIVES.md`:**

> A key is a verb or a question, never a goal.

Twelve keys violate that rule today. They do not change the machine and they do not ask the
screen anything; they name a *thing the author wanted*. Each one is a keyword the file says and
the run does not read.

## 1. The five overlaps to merge

### 1.1 `settle:` / `wait:` / `wait_after:` → `settle:` only

Already done for the vocabulary; `wait_after:` is MIGRATED in 33 files. What is **not** done is
the second half: nothing stops a file writing `settle: 60` where a fact exists.

| today | v0.0.2 |
|---|---|
| `settle: 60` followed by a `check:` of the same region | **a load error** |
| `settle: 60` with no check anywhere after it | allowed, and the log says `waiting 60s (no fact to wait on)` |

The validator already notices this pair (`settle:` then a `check:` of the same region). v0.0.2
makes it fail instead of warn, and prints the replacement in the message:

```
daemon.yaml:41: `settle: 60` at line 41 is followed by a check of the same region at line 44 -
  the fact exists, so wait for it: `loop: {check: …, until: …}` with `max` and `settle` inside `do:`
```

**Measured reason:** 28 of the 818 `settle`/`wait_after` uses are immediately followed by a real
measurement of the same screen, and two of those failed cachyos and endeavouros on CI — the guess
was right on the measuring machine and wrong on the runner.

### 1.2 `click:` / `at_button:` / `at_color:` / `double:` / `at_bottom:` / `at_fallback:` → `click:`

Six keys, one idea: press at a place. They differ only in *how the place is named*.

```yaml
# v0.0.1 - four keys for four ways of naming a point
- click: [936, 628]
- at_button: [703, 336]
- at_color: [255, 0, 0]
- double: [292, 927]
- at_bottom:  [10, 1]        # 8 uses

# v0.0.2 - one key, and the VALUE says how the point is found
- click: [936, 628]                          # a coordinate
- click: {button: [703, 336]}                # inside a window, by position
- click: {colour: [255, 0, 0]}               # the largest blob of one colour
- click: [292, 927]                          # `double: true` beside it
- click: [10, 1]                             # `anchor: bottom` beside it
```

`at_fallback:` becomes `click: {button: […], fallback: […]}`. `at_bottom:` becomes
`click: […], anchor: bottom`.

**Why a value and not four keys:** the four keys are the same verb with a different *address
form*, which is exactly what a mapping value is for — the same shape `check:` already uses for
`mode:`. It also removes the trap that `at_button` and `at_color` are not `click`, so a reader
looking for "how does this file press things" has to know all six.

### 1.3 `when:` / `when_not:` / `when_not_any:` / `check:` → `when:` with a value

Four ways to ask a question of the screen, and they mean two different things:

| key | question | what happens when false |
|---|---|---|
| `when: [a, b]` | does the screen say a AND b | step skipped |
| `when_not: [a, b]` | does the screen say NO a AND NO b | step skipped |
| `when_not_any: [[a],[b]]` | is NONE of these sets present | step skipped |
| `check: {…}` | one arbitrary question | **nothing** unless `until:`/`if:`/`must:` reads it |

**v0.0.2 keeps all four names but makes `check:` unable to be useless:**

- a `check:` with no `until:`, no `if:` and no `must: true` **in the same file** is a load error,
  because the answer is bound and never read. (This is the bug that let a screenshot comparison
  fail silently on run 44280999011 while the run reported success.)
- `when_not_any:` is folded into `when:` as `when: {none: [[a],[b]]}`, since it is the same
  question with a negation the name already carries elsewhere.

Measured: `when:` 16, `when_not:` 10, `when_not_any:` 0. The zero is why folding it costs
nothing — nothing writes it, and the alternatives form is the one people reach for when a pane
can announce itself in two ways (opensuse-tumbleweed's `welcome` reads back as `Wesn Home`).

### 1.4 `see:` / `ocr:` → `see:` only

`ocr:` is MIGRATED (118 uses converted). Nothing to do except delete the parser branch, which is
still reachable through the old spelling.

### 1.5 `boot` / `disk` / `disk_gb` → one `machine:` block

Three keys describe one thing: what machine to build.

```yaml
# v0.0.1
- boot: true
  os: linux
  memory_mb: 4096
  disk: disk.qcow2
  disk_gb: 128

# v0.0.2
- boot:
    os: linux
    memory: 4096
    disk: {file: disk.qcow2, size: 128}
```

`memory_mb` is `memory:` (the unit is in the name of the old key and in no other). `disk_gb`,
`disk_gpt`, `disk_esp_mib`, `disk_min_mb`, `disk_settle` all become fields of `disk:`.

**Measured:** `disk_gb` 30, `disk_gpt` 3, `disk_esp_mib` 2, `disk_min_mb` 2, `disk_settle` 1.
Five keys for one file's size and layout.

## 2. The twelve "goal" keys to delete

Each names something the author wants and no code reads. Deleting them is the whole point of the
rule at the top of this document.

| key | uses | what replaces it |
|---|---|---|
| `skip_when_unfinished` | 5 | `if: finished` |
| `until` / `until_any` | 79 / 0 | `loop: {until: …}` |
| `require` | 0 | `needs:` |
| `press` | 0 | `key:` |
| `sweep` | 0 | `loop: {do: [{click: …}]}` |
| `until_dark` | 0 | `check: {colour: {mean: {less_than: N}}}` |
| `wait_for_change` | 0 | `check:` + `loop:` |
| `change_settle` / `change_timeout` | 0 | `settle:` / `timeout:` |
| `graceful` | 0 | `shutdown: {method: …}` |
| `snapshot` | 0 | (deleted — its branch called `notImplemented`) |
| `reboot` | 0 | (deleted — `boot:` of a running machine is already a no-op) |
| `demo_script` | 0 | `write:` |
| `host_log` | 0 | (deleted — no branch) |
| `want` / `all` / `any` / `not` / `minus` | 0 | `check:` |

`until:` at 79 uses is the interesting one: **`until:` exists, is documented, and is used by
files while `loop: {until:}` does the same work.** Two spellings for one fact is worse than one,
because a reader has to check which file uses which.

## 3. What "simpler" should mean, concretely

The number that matters is not the key count. It is **how many keys a reader must hold in their
head to read one file**. Today, reading `ubuntu/steps/ssh.walk` needs these:

```
boot, os, memory_mb, timeout, loop, check, from, mode, name, words, rect, rect_at, scale,
see, until, fact, click, settle, type, type_gap, key, run, terminal_wait, ssh, scp, qga,
needs, require_ssh, ssh_probe, shutdown, wait_until, compress
```

32 keys for a file that installs openssh and proves it. v0.0.2's target is 20, by folding the
four click keys into one, the three disk keys into `disk:`, and `settle` into a value of `loop:`.

---

## 4. Migration, and why it is not a flag day

Every renamed key keeps its old spelling as an **alias that logs once and forwards** for one
release, the way `wait_after:` → `settle:` was done. The audit test (`internal/step/audit_test.go`)
already enforces "the table names a key the code lacks / the code declares a key the table omits",
so the alias period is checkable rather than remembered.

The order matters:

1. Delete the twelve goal keys (nothing uses them; no file changes).
2. Fold the four click keys into `click:` (mechanical; the audit test counts them).
3. Fold the disk keys into `disk:` (30 + 3 + 2 + 2 + 1 uses to rewrite).
4. Make `settle:`-then-`check:` a load error, file by file, starting with the two that failed CI.
5. `when_not_any:` → `when: {none: …}` (0 uses).

Steps 1, 2 and 5 touch no walkthrough. Step 3 touches 38 lines. Step 4 is the one that changes
behaviour, and it is the one with a measured reason.

---

## 5. What this pass will NOT do

- **It will not remove `settle:`.** Some waits have no fact — a window animating, a guest
  finishing its own shutdown. Removing it would force a fake check.
- **It will not merge `run:` / `ssh:` / `adb:`.** They are one shape but three different
  transports, and a file that says `ssh:` is saying "this must work over the network" — which is
  a claim worth seeing.
- **It will not touch `rect:`'s fraction form.** It is the one place the vocabulary got it right:
  a fraction cannot be measured at the wrong size.
- **It will not make `check:` mandatory anywhere.** `see:` measuring numbers is the primitive
  that replaced four `Is…Desktop` predicates; folding it back into `check:` would undo that.
